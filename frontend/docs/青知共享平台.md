# 青知共享平台

# 项目概述

同学你好，我们非常高兴你能参与到 Werun 实验室后端 Java 方向 2026 暑期纳新。

考试周刚刚落下帷幕，你是否还会记得考前焦头烂额到处寻找资料的情景？零零星星的资料收集给期末周的复习更添一层阻碍。所以秉持着开放共享的理念，我们这次准备开发一个资料共享平台——青知。

本阶段项目作业旨在开发一套在线资源共享系统的登录注册模块。系统支持教师和学生发布资源，查看资源，管理员进行系统管理的完整生态。

# 项目内容

## 用户认证

### 1\.1  用户注册

管理员的账号固定（例如：用户名 Admin，密码 Admin2026）

- 批量创建：管理员可上传教师/学生的信息Excel 文件，包含所需的信息（表头示例在下文给出）,系统根据 Excel 创建用户账号（注意用户名和初始密码的设置）。

- 自行创建：

1. 学生通过学号作为账号注册

2. 教师通过工号作为账号注册

3. 密码自拟（至少8位，包含数字和字母，要对输入密码进行验证）

- 双通道并行：系统校验该学号/工号是否已存在（Excel 已导入则提示"账号已存在，请直接登录"）。两种方式创建的账号统一管理

### 1\.2 用户登录

- 用户通过 账号\+密码 登录。

- 通过 Filter（过滤器） 或 Interceptor（拦截器） 搭配 JWT** **实现用户在访问非登录注册接口时，会返回“未登录”提示。

### 1\.3 密码管理

- 密码加密存储，使用任意加密算法（例如 MD5）处理存储时的密码信息。

### 1\.4 字段说明

- 学生字段：学号、姓名、手机号、邮箱、院系、专业

- 教师字段：工号、姓名、手机号、邮箱、院系

## 角色权限

### 2\.1 管理员权限

管理员拥有系统的最高权限，可以管理平台的所有功能模块。

#### 2\.1\.1用户管理

管理员能够对所有用户信息进行增删改查操作，包括重置用户密码。

#### 2\.1\.2资源管理

管理员会对发出来的资源进行审核，只有审核通过才可以发布。同时可以对资源进行增删改查。

#### 2\.1\.3数据导入管理

管理员可以通过上传符合规范的 Excel 批量导入师生信息，导入时也要对Excel的账号密码信息进行合法性验证（如学号/工号格式是否正确、是否重复、必填字段是否完整等）

#### 2\.1\.4加分项

对批量导入信息提供完善的导入错误处理机制和数据回滚功能，当导入过程中出现问题时，可以快速恢复到导入前的状态,并且报告给管理员用户

### 2\.2用户权限

#### 2\.2\.1 **个人信息管理**

用户可以查询，补充自己的个人信息，修改密码，查看自己发布的资源和收藏列表（分页），支持收藏和取消收藏操作

#### 2\.2\.2资源的增删改查

1. 用户可以发布，删除，修改自己发布的资源，可以查看所有发出来的资源，支持按**发布时间**进行范围查询（指定起止日期），对查询结果按时间倒序分页展示。

2. 用户可以收藏感兴趣的资源

## 资源信息

- 资源标题、资源描述、所属课程

- 上传的文件（支持 PDF、PPT、Word、图片等常见格式，单文件大小不超过 50MB）

- 发布者信息（关联用户）、发布时间、审核状态

- 资源文件存储于服务器本地目录或对象存储中

## 一些细节

- 全局异常处理实现集中捕获异常与用户友好提示。

- 通过SLF4J组件进行必要的日志打印与跟踪。

- Excel导入示例表头：

- 注明资源状态流转：

- 用户"提交"资源后状态为`待审核`，仅本人和管理员可见。

- 管理员审核通过后状态变为`已通过`，所有用户可见。

- 管理员审核拒绝后状态变为`已拒绝`，审核拒绝时需填写拒绝理由，用户可修改后重新提交。

- 用户可随时删除自己的资源（任意状态）。

- 已通过的资源被修改后，状态回退为`待审核`。

## 特色功能模块（加分项）

### 在线预览功能

同时提供在线预览功能，方便师生直接浏览PPT内容。

比如:OpenOffice,IOUtils等等

### 接口限流与防刷机制

对登录接口实现防暴力破解机制：同一账号在 5 分钟内连续登录失败 5 次后，锁定该账号 15 分钟。对文件上传接口实现频率限制：同一用户每分钟最多上传5 个文件。

### 资源文件去重（秒传）

用户上传文件时，系统先计算文件的 **MD5/SHA\-256 哈希值**，与数据库中已有文件的哈希值比对。若发现相同文件已存在，则直接关联已有文件记录而非重复存储，实现"秒传"效果。

## 分包规范（只是示例，与项目无关）

![image\.png](图片和附件/image.png)

- **config**：用于集中管理和配置应用程序的各种组件、属性和资源。

- **controller**：作为应用程序的前端接口，负责接收用户的请求，调用业务层处理请求，并将处理结果返回给用户。

- **entity**：定义与数据库表一一映射的实体类，表示数据库中的数据模型。

- **mapper**：负责与数据库进行交互，实现数据的持久化操作，如查询、插入、更新、删除等。

- **service**：封装业务逻辑，实现应用程序的核心功能和业务规则。

- **util**：提供一些通用的工具类和方法，用于辅助应用程序的开发和运行。

- **dto，vo**：封装数据层，暂时不用考虑。
